# MMWB Internal API v1

Внутренний API для сервисов-партнёров. Только чтение. Один токен = один клиент.

## Auth

Каждый запрос должен содержать заголовок:

    X-Api-Token: <выданный токен>

Токен выдаёт владелец бота. Запрос без токена или с неверным — 401.

## Endpoints

### GET /api/v1/address/{username}

Возвращает адрес кошелька пользователя бота по его Telegram-username.

- `username` — префикс `@` допускается и отсекается сервером; регистр не
  важен (нормализуется к lowercase).

**Ответы:**

| Статус | Тело | Когда |
|--------|------|-------|
| 200 | `{"username": "alice", "address": "GABC..."}` | Пользователь найден, адрес определён |
| 404 | `{"error": "not_found"}` | Нет такого username ИЛИ нет ни адреса, ни кошелька |
| 401 | `{"error": "unauthorized"}` | Токен отсутствует или неверный |
| 500 | `{"error": "internal"}` | Ошибка на стороне бота |

Определение адреса — как в самом боте при выплате: сначала персональный
`default_address` пользователя; если он не задан или не похож на
публичный ключ Stellar (56 символов, префикс `G`) — публичный ключ
кошелька пользователя по умолчанию (`MYMTLWALLETBOT.default_wallet=1`).

404 единый для «нет юзера» и «нет адреса» — API не раскрывает наличие регистрации.

Запрос с пустым username (`GET /api/v1/address/`) не попадает в роут и
обрабатывается HTTP-сервером как обычный 404 (text/plain, без JSON-тела).

## Примеры

    curl -H "X-Api-Token: $TOKEN" http://127.0.0.1:8082/api/v1/address/alice

    # 200
    {"username": "alice", "address": "GAEO4Z...NWLP2M"}

## Ограничения

- Сервис слушает внутренний интерфейс и наружу не публикуется; доступ только
  с того же сервера (или из согласованной docker-сети).
- Токен статичен до ротации; ротация — по запросу владельцу.
- API в стадии v1: поле `address` может добавиться к другим данным, удаление
  полей — только в v2.
