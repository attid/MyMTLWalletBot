# e2e-send: E2E send XLM on testnet, free-wallet guard probe

## Context

Second E2E slice: walk the real `/send` wizard (message → address → token →
amount → confirm → PIN) against the testnet and verify the money actually moves.
The same harness probes the free-wallet guard, which ADR-0003 says must block
native XLM spending.

Result: the normal send works end to end (2 XLM arrive at the recipient, the
signature is built with the testnet passphrase, submission goes through the
horizon pool). The free-wallet case revealed a real defect: the policy is not
applied when the transaction is signed through `SigningFacade`, so a free wallet
spends XLM via `/send`. That test is kept as `xfail(strict=True)`.
