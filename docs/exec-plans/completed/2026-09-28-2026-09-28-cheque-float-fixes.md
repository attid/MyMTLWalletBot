# 2026-09-28-cheque-float-fixes: Fix float garbage and universal fsm_after_send app_context

## Context

Cheque creation crashed with float garbage (`str(0.2*3)` = `0.6000000000000001` → stellar_sdk ValueError), WebApp signing path called `fsm_after_send` without `app_context` (TypeError after successful submit — cheque row never created), cancel/claim paths ignored `submit_transaction()` result (false "чек выплачен"), and UI showed raw float products (`2.4299999999999997`, `7.720000000000001`). User ordered a project-wide float sweep and a universal `fsm_after_send` mechanism.

## Change Plan

1. [x] `create_cheque.py`: format `total_amount` with `.7f` before sending to `build_payment_transaction`.
2. [x] `signing_worker.py`: pass `app_context` to `fsm_after_send` via signature introspection (universal, heals cheque/donate/usdt/balance/buy flows).
3. [x] `cheque.py`: check `submit_transaction()` result dict in `cmd_cancel_cheque` and `cmd_send_money_from_cheque` before success message.
4. [x] Display: `float2str` for cheque totals in `cheque.py` (creation screen + resend) and trade display lines in `trade.py`.
5. [x] `send_payment.py` + `manage_offer.py`: normalize float amounts/prices with `.7f` at Stellar boundary.
6. [x] Add/update tests: worker introspection (app_context flows), create_cheque formatting, cheque display.
7. [x] Run `just check-fast` (lint + test-fast + arch-test); smoke scripts for before/after repro.
