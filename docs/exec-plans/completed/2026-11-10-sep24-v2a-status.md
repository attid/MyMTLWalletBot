# sep24-v2a-status: SEP-24 V2a: status screen, payment instructions, trustline preflight

## Context

V1 (`docs/exec-plans/completed/2026-11-10-sep24-v1-compliance.md`) makes SEP-24
spec-compliant, but the bot still dead-ends after the interactive link: the
transaction id is stored and never used, and the payment instructions the anchor
returns (modern `instructions.amount_in`, legacy `withdraw_anchor_account`, a
muxed `M` destination or a `more_info_url` page) are never shown. Withdrawals
therefore stall in `pending_user_transfer_start` unless the user finds the
address on the anchor's own page, and deposits are silent.

This slice adds the smallest possible feedback loop: one "Check status" button
on the SEP-24 screen, one status view that shows the localized status, amounts,
instructions and `more_info_url`, plus a trustline warning before a deposit can
fail. No polling worker, no automatic payments (that is V2b).

## Risks / Open Questions

- Status reads reuse the cached SEP-10 token only. If the anchor issued a
  short-lived token (10 minutes, test anchors) the user is asked to authorize
  again through the already existing deposit/withdraw callback.
- Muxed `M` destinations are displayed verbatim with an explicit warning; the
  bot still does not pay them itself.
- No background polling yet, so statuses update only on refresh.

## Outcome (2026-11-10)

- SEP-24 screen now has a "Check status" button (`Sep24Status`) next to the
  anchor link; the keyboard labels are localized (`kb_sep24_*`).
- Status screen renders the localized status (including the legacy
  `pending_user_transfer_start` wording), type, transaction id, amounts, fee,
  anchor `message`, the anchor `more_info_url` and, when the anchor publishes
  them, the payment instructions: destination (muxed `M` shown verbatim with an
  explicit warning), memo and asset.
- Deposit status warns when the wallet has no trustline for the asset
  (Horizon balance check).
- Status is read with the cached SEP-10 token only: `Sep24ReauthRequired` turns
  into a "Authorize again" button that replays the original deposit/withdraw
  callback, so no PIN/signature is requested for a plain status refresh. A 401
  from the anchor drops the cached token first.
- `GET /sep24/transaction` parsing lives in `sep24/view.py` and returns
  `Sep24TransactionView` (facade `fetch_sep24_transaction` /
  `fetch_sep24_transaction_cached`).
- Still out of scope (V2b): background polling/notifications, automatic
  payments, muxed-destination prefill.
